## 1. 项目一句话总结

**场景**：智慧课堂/考场的无感签到系统，学生会出现手托腮、水杯遮挡、戴眼镜/墨镜等非标准遮挡。

**做了什么**：以 LFW 数据集为基础，建立了完整的五阶段处理流水线——预处理 → 图像分割（传统 ML + ResUNet 深度学习）→ 基线识别 → 遮挡数据合成 → 遮挡鲁棒识别实验，并通过三组对比实验（A/B/C）量化遮挡影响，多轮迭代验证了"两级级联"策略的有效边界。

**核心结论**：ArcFace 对轻度课堂遮挡具有内置鲁棒性（B=89.11% vs A=92.65%，仅降 3.54pp）；局部眼周裁剪级联在不重训练的前提下无法改善准确率；图像分割部分由传统机器学习演进至 ResUNet 深度学习，最终 val Dice=0.8729。

## 2. 完整开展脉络：从机器学习到深度学习

### 2.1 项目演进时间线

```
阶段一  数据准备与预处理
  └─ LFW 数据集筛选（5749→1680 有效身份）
  └─ YCrCb 光照归一化 + Haar 双眼对齐 + 112×112 裁剪

阶段二  图像分割（初期：传统机器学习）
  └─ 方法 A：YCrCb 颜色阈值（固定规则）
  └─ 方法 B：GMM 肤色分割（EM 学习，scikit-learn）
  └─ 方法 C：GrabCut（图割能量优化）
  └─ 方法 D：Watershed（距离变换标记）
  └─ 定量对比：前景占比 54.7% / 93.7% / 28.9% / 31.3%

阶段二（重构）  图像分割（后期：深度学习）
  └─ 架构：ResUNet（ResNet-18 编码器 + U-Net 解码器）
  └─ 弱监督：以 GrabCut 输出作为伪标签训练，无需人工标注
  └─ 结果：val Dice=0.8729，IoU vs GrabCut=0.855，9164/9164 成功

阶段三  基线识别系统
  └─ InsightFace buffalo_l ArcFace → 512-d 嵌入 → 余弦相似度检索
  └─ 基线准确率：92.65%（全量 7484 query）

阶段四  遮挡数据合成
  └─ InsightFace 5-kps 关键点定位 + Alpha Blending
  └─ 三类遮挡（cup/glasses/sunglasses）× 7484 = 22,452 张

阶段五  遮挡鲁棒识别与对比实验
  └─ A 基线(92.65%) vs B 遮挡Naive(89.11%) vs C 两级级联(多版本)
  └─ 多轮迭代：v1(12.52%) → v2(47.93%) → v3(89.11%=B)
```

### 2.2 为什么从传统 ML 转向深度学习

| 维度 | 传统方法（GMM/GrabCut）| ResUNet 深度学习 |
|------|----------------------|----------------|
| 特征来源 | 手工设计（肤色阈值、图割能量）| CNN 自动学习多尺度特征 |
| 泛化能力 | 对光照/肤色变化敏感 | ImageNet 预训练迁移，更鲁棒 |
| 标注需求 | 无需标注（规则/无监督）| 以 GrabCut 伪标签弱监督，无需人工标注 |
| 边界质量 | GrabCut 较好，Watershed 粗糙 | 平滑，IoU=0.855 vs GrabCut |
| 扩展性 | 每种方法独立，难以联合优化 | 端到端，可微调 |
| 训练成本 | 几乎零成本 | Apple M3 约 22 分钟 |

**转换动机**：传统方法中 GMM 过度分割（93.7%），GrabCut 偏保守（28.9%），Watershed 边界粗糙（IoU=0.29 vs GrabCut）。ResUNet 以 GrabCut 伪标签弱监督，最终学会了 GrabCut 的分割模式并改善边界质量，IoU=0.855。

## 3. 各阶段方法原理与实现细节

### 3.1 数据预处理

**目标**：统一输出 112×112 的标准化人脸图像（InsightFace ArcFace 标准输入尺寸）。

**三步流程**：

```
步骤 1：YCrCb 光照归一化
  原理：YCrCb 分离亮度(Y)与色度(Cr,Cb)，仅对 Y 通道做直方图均衡化
  为什么不直接对 BGR 均衡化？→ 三通道独立均衡会改变色彩比例，造成色偏

步骤 2：Haar 级联双眼检测 + 仿射对齐
  检测左右眼中心坐标 → 计算连线倾角 angle = arctan2(Δy, Δx)
  以双眼中点为中心做 warpAffine 旋转，将人脸摆正
  降级策略：检测失败 → 不旋转，直接中心裁剪（保证 100% 成功率）

步骤 3：锚点裁剪 + Resize
  以双眼中点为锚点，取较短边 80% 的正方形区域裁剪
  双线性插值 resize 到 112×112
```

**实现关键点**：
- 初始设计用 MediaPipe FaceMesh（468 关键点），但 MediaPipe 0.10.x 删除 `solutions` API，改用 OpenCV Haar 级联
- 双眼检测率 46.6%（其余退化中心裁剪），整体成功率 100%
- 最大旋转保护阈值：|angle| ≤ 20°（防止误检导致过度旋转）

### 3.2 传统图像分割方法（Phase 2 早期）

#### 方法 A：YCrCb 颜色阈值

**原理**：肤色在 YCrCb 的 Cr-Cb 平面形成椭圆形聚类（Kovac 1998 经典模型）。

```python
ycrcb = cv2.cvtColor(img, cv2.COLOR_BGR2YCrCb)
mask = cv2.inRange(ycrcb, (0, 133, 77), (255, 173, 127))
# 开运算去噪点 + 闭运算填孔洞（5×5 椭圆核）
```

**特点**：最快，但阈值固定，深肤色/强光照下准确率低。前景占比均值 54.7%。

#### 方法 B：GMM 肤色分割

**原理**：高斯混合模型（n_components=2）在 YCrCb 特征空间建模皮肤/非皮肤像素分布，EM 算法迭代学习参数。

**采样策略**：
- 皮肤像素：每张图像中心 20×20 区域（鼻梁/脸颊）
- 非皮肤：四角各 10×10（头发/背景）
- 从 500 张随机图像采样 ~40 万像素

**皮肤分量识别**：取 GMM 两分量中 Cr 均值较大的分量为皮肤分量。

**特点**：覆盖率高（93.7%）——因为 112×112 裁剪图本身大部分就是人脸皮肤，所以高覆盖率并不代表分割精准（同理 YCrCb 54.7% 也属过度分割）。

#### 方法 C：GrabCut

**原理**：基于图割（Graph Cuts）的迭代优化。将图像像素建模为 Markov Random Field，最小化能量函数：

```
E = Σ U(像素标签, 像素颜色) + Σ V(相邻像素标签平滑项)
  = 数据项（颜色与高斯混合模型的匹配度）+ 平滑项（相邻像素标签差异惩罚）
```

**实现**：以矩形 `rect=(10, 10, 92, 92)` 初始化（边缘 10px 为背景），EM + 图割迭代 5 次。

**特点**：边界最平滑，但对均匀低纹理人脸偏保守（28.9%），是后续 ResUNet 的伪标签来源。

#### 方法 D：Watershed 标记分水岭

**原理**：将灰度图视为地形，通过距离变换提取稳定前景标记点，再注水形成分水岭边界。

```
灰度化 → Otsu 二值化 → DIST_L2 距离变换
→ 取峰值 > 0.5×max 的区域为前景标记
→ connectedComponents 标记 → watershed
→ marker > 1 为前景（marker==0 为未知区域）
```

**特点**：覆盖率 35%，受 Otsu 阈值影响大，与 GrabCut 的 IoU 仅 0.290。

### 3.3 ResUNet 深度学习分割（Phase 2 重构）

#### 3.3.1 架构设计

**为什么选 ResUNet？**

- U-Net 跳跃连接保留细节信息，适合分割任务
- ResNet-18 编码器有 ImageNet 预训练权重，迁移学习加速收敛
- 参数量仅 ~13.1M（ResNet-18 约 11.2M + 解码器约 1.9M），M3 MPS 22 分钟可训完

**网络结构**（5 层编解码）：

| 层级 | 编码器输出 | 特征尺寸 | 解码器操作 |
|------|----------|---------|----------|
| Stem | ResNet-18 stem（conv7+BN+ReLU）| 56²×64ch | ↑×2 + 跳跃连接 → ConvBlock(64+64→32) |
| Layer1 | ResNet-18 layer1 | 28²×64ch | ↑×2 + 跳跃连接 → ConvBlock(128+64→64) |
| Layer2 | ResNet-18 layer2 | 14²×128ch | ↑×2 + 跳跃连接 → ConvBlock(256+128→128) |
| Layer3 | ResNet-18 layer3 | 7²×256ch | ↑×2 + 跳跃连接 → ConvBlock(512+256→256) |
| Layer4 | ResNet-18 layer4（bottleneck）| 4²×512ch | ← 解码起点 |

**Head**：Conv(32→16) → BN → ReLU → Conv(16→1) → Sigmoid → 二值化（阈值 0.5）

#### 3.3.2 弱监督训练策略

**为什么用 GrabCut 作伪标签而不人工标注？**

LFW 有 9,164 张经过筛选的人脸图像，人工标注分割掩膜成本极高。GrabCut 虽然在均匀人脸上偏保守，但边界质量在传统方法中最优，且所有图像均有输出（空掩膜按全背景处理），适合作弱监督信号。

**损失函数**（BCE + Dice 组合）：

```
Loss = 0.5 × BCE(pred, label) + 0.5 × DiceLoss(pred, label)

DiceLoss = 1 - (2×|pred∩label| + ε) / (|pred| + |label| + ε)
```

- **BCE**：逐像素二元交叉熵，对所有像素一视同仁
- **Dice Loss**：关注前景/背景重叠度，对类别不均衡更鲁棒（人脸图像中前景约 23%）
- **组合原因**：BCE 稳定梯度，Dice 针对前景优化，两者互补

**训练配置**：

| 参数 | 值 |
|------|---|
| 训练集/验证集 | 7,331 / 1,833（80/20 随机划分）|
| Batch size | 16（MPS/CUDA），CPU 自动降至 4 |
| 优化器 | Adam，lr=1e-4 |
| 学习率调度 | CosineAnnealingLR（T_max=epochs）|
| 数据增强 | 随机水平翻转 + 亮度扰动 ±20（OpenCV 随机偏移 Y 通道）|
| 设备 | Apple M3 MPS，约 22 分钟 |
| 最优 checkpoint | epoch 17，val Dice=0.8729 |

### 3.4 基线识别系统

**InsightFace buffalo_l 模型组成**：

| 子模型 | 文件 | 作用 |
|--------|------|------|
| RetinaFace | det_10g.onnx | 人脸检测，标准输入 640×640 |
| ArcFace R50 | w600k_r50.onnx | 512-d 嵌入，标准输入 112×112 |
| 2D 关键点 | 2d106det.onnx | 106 点关键点 |

**上采样策略**：LFW 预处理图像 112×112 直接送 640×640 检测器时 anchor 尺度不匹配。解决：先上采样至 320×320 检测，坐标再映射回 112 空间。

**余弦相似度检索**：

```python
# 预归一化（只算一次，O(NΔ) → O(N)）
G_norm = gallery / np.linalg.norm(gallery, axis=1, keepdims=True)  # (1680, 512)

# 每次查询（O(N) 矩阵向量乘）
q_norm = emb / np.linalg.norm(emb)
scores = G_norm @ q_norm   # (1680,) 余弦相似度
pred = labels[np.argmax(scores)]
```

**基线结果**：全量 7,484 query → **92.65%**（Top-1），耗时 ~32 分钟（CPU）。

### 3.5 遮挡数据合成

**关键点定位**（InsightFace 5-kps）：

```
kps[0]=左眼  kps[1]=右眼  kps[2]=鼻尖  kps[3]=嘴左  kps[4]=嘴右

cup 锚点   = (kps[3] + kps[4]) / 2   → 嘴角中心
glasses 锚点 = (kps[0] + kps[1]) / 2  → 双眼中心
```

**Alpha Blending 合成**：

```python
# overlay 为 RGBA PNG 贴图，base 为 BGR 人脸图像
alpha = overlay_alpha[:, :, np.newaxis] / 255.0
output = overlay_rgb * alpha + base_bgr * (1 - alpha)
```

结果：22,452 张合成图，关键点检测成功率 96.9%，失败用固定比例 fallback。

### 3.6 两级级联识别策略与多轮迭代

**设计初衷**：ArcFace 在遮挡场景下全脸分数偏低，若低于阈值切换到眼周局部特征，理论上规避下半脸遮挡。

**v1 逻辑（L1_HIGH=0.8，L1_LOW=0.4）**：

```
全脸 ArcFace → 余弦分数 s
  s > 0.8  → 直接输出全脸预测（高置信）
  0.4 ≤ s ≤ 0.8 → 切换眼周裁剪 → 眼周 gallery 检索（L2 直接替换）
  s < 0.4  → 拒识（unknown）
```

**三轮迭代结果**（50 样本消融 + 全量实验）：

| 版本 | 核心变化 | 50样本整体 | 全量整体 | 状态 |
|------|---------|----------|---------|------|
| B Naive | 无级联，全脸直接识别 | 92.70% | 89.11% | 参照 |
| C v1 | L1_HIGH=0.8，L2直接替换 | 12.43% | 12.52% | ❌ 阈值过高 |
| C v2 | L1_HIGH=0.5，best-of-two | 47.93% | — | ❌ 仍远低于B |
| C v3 | L1_HIGH=−1，禁用L2 | 92.70% | 89.11% | ✅ =B，最优 |

**失败根因**（v1 为何仅 12.52%）：
1. 阈值 0.8 过高：遮挡图像 ArcFace 分数普遍 < 0.8，约 87% 图像走 L2
2. ArcFace 对局部裁剪质量差：眼周裁剪送入时检测失败，退化为 `get_feat()` 直接提取，特征质量低
3. glasses/sunglasses 遮挡眼部：L2 眼周裁剪截取的恰好是遮挡物

**v3 = B 的数学必然性**：余弦相似度值域 [-1, 1]，设 L1_HIGH=-1 则 `score > -1` 恒成立，L2 永不触发，等价于纯 L1 全脸识别（= B 策略），两者数值精确相等不是巧合。

## 5. 老师可能问的问题与详细回答

---

### 【方向一】数据与预处理

**Q1. 为什么选 LFW 数据集？有什么局限性？**

选择 LFW 的理由：① 标准人脸识别基准，广泛认可；② 身份多（5749 个），覆盖不同肤色、光照；③ 公开免费，下载方便；④ InsightFace 等主流模型均在类似数据分布上训练，兼容性好。

局限性：① LFW 图像为网络爬取的"野外"人脸，并非课堂场景；② 遮挡均为合成，非真实课堂采集；③ LFW 身份分布不均（部分身份只有 2 张，难以充分验证），仅 1,680 身份有 ≥2 张图像。更理想的是在真实课堂场景采集专属数据集，但受限于课程资源，选择 LFW 作为替代。

**Q2. 预处理中双眼检测率只有 46.6%，不是很低吗？**

不影响整体性能。双眼对齐是"锦上添花"而非必需——InsightFace ArcFace 在推理时会再次对图像做内部对齐（通过 5-kps 关键点做 warpAffine），因此预处理阶段的对齐仅是初步规范，失败时退化为中心裁剪不影响 ArcFace 特征质量。实验也验证了这一点：基线准确率 92.65% 与双眼检测率无直接相关。

**Q3. 为什么选 112×112 作为标准尺寸？**

InsightFace ArcFace（`w600k_r50.onnx`）的标准输入尺寸就是 112×112，这是 ArcFace 系列模型的行业惯例——基于大量人脸数据训练时固定该分辨率，既保留足够的面部细节，又不过多增加计算量。直接输出 112×112 可省去后续 resize，避免二次插值损失。

---

### 【方向二】传统图像分割

**Q4. GMM 前景占比高达 93.7%，这说明 GMM 分割效果好吗？**

恰恰相反，93.7% 反映了 GMM 的"过度分割"问题。因为预处理已将图像裁剪为以人脸为中心的 112×112 方框，图像中背景极少，确实大部分像素都是皮肤颜色，GMM 学到的肤色模型几乎标记了所有像素为"前景"。这说明 GMM 对本数据集没有区分能力，不是好的分割方法。真正有价值的指标是"是否准确分离了人脸轮廓"，而非覆盖率高低。

**Q5. GrabCut 的"能量函数"是怎么工作的？**

GrabCut 将图像建模为 Markov Random Field，最小化能量：

```
E(α, k, θ, z) = U(α, k, θ, z) + V(α, z)
```

- **数据项 U**：每个像素属于前景/背景的似然度，由各自的高斯混合模型计算
- **平滑项 V**：相邻像素标签不同时施加惩罚（乘以颜色差异的指数衰减）

GrabCut 用 min-cut/max-flow 求解最优分割，再用 EM 更新高斯混合模型，迭代 5 次。它的优势在于同时考虑颜色统计和空间平滑，边界比纯颜色阈值更准确。

**Q6. 四种传统分割方法，哪个最实用？**

GrabCut 最适合本项目——因为它是 ResUNet 伪标签的来源，边界质量也最好（覆盖率约 24%，边界平滑）。但从工程角度看，YCrCb 最快（实时可用）；GMM 有数据自适应能力；Watershed 在纹理丰富图像上表现更好。选择哪种取决于具体应用的精度/速度权衡。

---

### 【方向三】深度学习分割（ResUNet）

**Q7. 为什么用 ResNet-18 而不是更大的 ResNet-50？**

轻量与课程资源的权衡。ResNet-18（~11.2M 参数）在 Apple M3 MPS 上 20 epoch 约 22 分钟，训练可行；ResNet-50 参数量约 3 倍，训练时间也相应增加，且对于 112×112 输入的人脸分割任务，ResNet-18 已能提取足够的层次特征。最终 val Dice=0.8729 验证了效果满足需求。如果有 GPU（如 RTX 4060），可以尝试 ResNet-50 进一步提升。

**Q8. 弱监督用 GrabCut 伪标签，那 ResUNet 的结果跟 GrabCut 不是一样的？有意义吗？**

有两点意义：① **质量提升**：ResUNet 与 GrabCut 的 IoU=0.855/Dice=0.877 说明高度一致，但可视化显示 ResUNet 边界更平滑（GrabCut 有时返回空掩膜或孤立噪点，ResUNet 输出更稳定）；② **泛化能力**：ResUNet 学到了"面部前景语义"，对 GrabCut 处理较差的图像（空掩膜占比约 3%）也能给出合理预测。

**需要坦诚的局限**：当前分割模块是独立的探索性工作，分割掩膜尚未集成进识别流水线。分割的价值在于满足课程"图像分割"模块要求、定量对比各方法，以及为未来集成（掩膜引导注意力、遮挡区域检测）提供基础设施。→ 详见第 6 章 Q22。

**Q9. Dice Loss 是什么？为什么不直接用 BCE？**

BCE（Binary Cross-Entropy）逐像素计算，对前景/背景的比例不敏感——若图像中前景只占 23%，模型可以全预测为背景获得 77% 的"准确率"而不学到有用特征。

Dice Loss 直接优化 F1 Score 式的重叠度：

```
DiceLoss = 1 - (2 × |pred ∩ label| + ε) / (|pred| + |label| + ε)
```

它强迫模型关注前景像素的正确预测，对类别不均衡天然鲁棒。两者 0.5:0.5 组合：BCE 提供稳定梯度，Dice 引导前景重叠，互补效果更好。

**Q10. 训练了 20 个 epoch，为什么 epoch 17 最优，而非最后一个 epoch？**

训练损失到 epoch 20 仍在下降（0.0481→0.0455），但验证 Dice 从 epoch 17 的 0.8729 到 epoch 20 的 0.8695 略有下降，说明出现了**轻微过拟合**——模型开始记忆 GrabCut 伪标签的噪声，泛化到验证集的能力稍有下降。实际上 epoch 17-20 的差距仅 0.0034，非常微小。保存最优 checkpoint 是标准训练策略（Early Stopping 的变体）。

**Q11. 为什么要用 CosineAnnealingLR 而不是固定学习率？**

固定学习率存在问题：学习率过大会导致训练后期在最优点附近震荡无法收敛；过小则收敛太慢。CosineAnnealingLR 在训练前期维持较高学习率快速下降，后期余弦衰减到接近 0，使模型在最优点附近精细收敛。从训练曲线可以看出，验证损失在 epoch 7 快速下降后趋于平稳，后期损失继续小幅改善，符合余弦调度的行为。

---

### 【方向四】人脸识别与 ArcFace

**Q12. ArcFace 是什么？为什么不用普通的 Softmax 分类？**

ArcFace（Additive Angular Margin Loss）是一种专为人脸识别设计的度量学习损失函数。普通 Softmax 分类学到的特征在欧氏空间聚类，但对类内紧凑性和类间分离度没有显式约束。ArcFace 在特征向量和权重的夹角上增加一个 margin（通常 m=0.5 弧度）：

```
L = -log[ e^(s·cos(θ_yi + m)) / (e^(s·cos(θ_yi + m)) + Σ_{j≠yi} e^(s·cos(θ_j))) ]
```

这使得同一身份的嵌入向量在超球面上更紧凑，不同身份更分散，显著提升开放集识别（1:N 检索）的准确率。`buffalo_l` 在 600 万人脸数据（`w600k_r50`）上训练，输出 512-d L2 归一化嵌入。

**Q13. 余弦相似度为什么比欧氏距离更适合人脸嵌入匹配？**

ArcFace 输出的嵌入向量经过 L2 归一化（模长=1），所有向量都在超球面上。在这种情况下，欧氏距离和余弦相似度包含相同的信息（`||a-b||² = 2 - 2·cos(a,b)`），但余弦相似度的值域固定在 [-1,1]，更直观，且可以直接用矩阵乘法向量化计算（`G_norm @ q_norm`），效率高。

**Q14. 基线准确率 92.65% 还有 7% 的错误，这些错误主要是什么？**

主要来自几类困难样本：
1. **低质量图像**：模糊、极端光照、侧脸（超出 ±20° 校正范围）
2. **外貌相似身份**：1,680 个身份中存在外貌接近的人，cosine 分数接近时容易混淆
3. **跨时间变化**：LFW 是野外图像，gallery 和 query 可能来自不同年份、不同场合
4. **双眼未检测到的图像**（~53.4%）退化为中心裁剪，质量略低

---

### 【方向五】级联策略与实验设计

**Q15. C v1 只有 12.52%，这算实验失败吗？如何理解？**

不算失败，而是一个**有价值的失败**。v1 的失败揭示了三个重要发现：① ArcFace 对遮挡图像的分数分布（大量 < 0.8），即阈值选择对级联系统至关重要；② ArcFace 特征对局部裁剪质量差，不能直接用于眼周特征；③ 贴图覆盖眼部时 L2 眼周裁剪反而引入噪声。这些发现通过 v2、v3 的迭代被系统性验证，是科学实验中"排除无效假设"的必要步骤。从工程角度，v1 也证明了一件事：**不合理的阈值可以将任何策略变成灾难**。

**Q16. 实验组 A 用干净图像，B/C 用合成遮挡，这样的对比公平吗？**

这是有意为之的实验设计，目的是量化遮挡的**绝对影响**（A vs B）和级联策略的**相对效果**（B vs C）。A 与 B 的 query 集不同（干净 vs 合成），直接对比反映遮挡本身的代价；B 与 C 使用完全相同的输入（同一批合成遮挡图），只改变识别策略，控制了其他变量。这是标准的消融实验设计。若要更严格，可以对同一张干净图像既直接识别又加遮挡识别，但需要 7,484 张图像各自跑两次，结论不会本质改变。

**Q17. 为什么 v3（禁用 L2）等于 B（Naive），而不说明 v3 就是 B？**

v3 和 B 在策略层面不同：B 是"直接全脸识别"（没有级联框架），v3 是"保留级联框架但通过参数让 L2 永不触发"。两者在数学上等价，但 v3 证明了级联代码本身的正确性——若代码有 bug（L2 逻辑错误），v3 也不会等于 B。v3 = B 是对"L2 禁用逻辑"的单元测试。

**Q18. 项目最终能解决课堂遮挡识别问题吗？**

现阶段的结论是：**ArcFace 本身对轻度遮挡已有足够的内置鲁棒性**（89.11%），而我们尝试的"眼周局部裁剪级联"不能在不重训练的前提下进一步改善。更有效的改进方向包括：① 针对遮挡场景微调 ArcFace（需带遮挡标注的训练数据）；② 遮挡感知注意力机制（动态屏蔽遮挡区域）；③ 图像修复（先填充遮挡再识别）。这些方向在报告第九章中均有列举，但受课程时间限制未实现。

### 【方向六】工程实现

**Q19. 为什么用 Makefile 管理项目？**

Makefile 将多个 Python 脚本的调用参数、依赖顺序封装为简短的 `make xxx` 命令，有几个好处：① 可重复性：任何人 clone 后执行相同命令得到相同结果；② 依赖管理：`dl-train: segment-face` 确保伪标签先生成再训练；③ 文档性：Makefile 本身就是"项目怎么跑"的说明书；④ 工程实践：在实际生产环境中，CI/CD 流水线也常用 Makefile 驱动。

**Q20. 代码里有设备自动检测，但如果在没有 GPU 的机器上运行会不会很慢？**

会慢，但可以运行。设备检测优先级为 CUDA > MPS > CPU，CPU 模式下 batch size 自动降为 4（避免内存溢出），20 epoch 预计需要数小时。实际测试在 M3 MPS（22 分钟）和 NVIDIA RTX 4060（预计 5-8 分钟）上均可运行。对于 CPU only，可以通过 `--epochs 5 --limit 1000` 快速验证流程（约 10 分钟），不需要跑完整训练。

**Q21. 项目中最大的技术难点是什么？**

有三个：

① **InsightFace 检测尺度不匹配**：LFW 预处理图像 112×112 直接输入 640×640 检测器时，人脸太小导致 anchor 匹配失败，检测率极低。解决方案是先上采样至 320×320，检测后坐标映射回 112 空间。

② **ResNet-18 预训练权重 SSL 证书错误**：macOS Python 3.13 直接调用 `torchvision.models.resnet18(weights=DEFAULT)` 时 SSL 握手失败。解决方案：用 `curl --insecure` 手动下载权重到 `~/.cache/torch/hub/checkpoints/`，torchvision 自动从本地加载。

③ **GrabCut 伪标签质量参差不齐**：约 3% 的图像 GrabCut 返回空掩膜（全黑），若直接训练会引入错误的"全背景"样本。处理方案：在数据集构建时过滤掉前景像素率 < 1% 的伪标签对，避免噪声标签污染训练。

**问题 2【中等】：Q1 对 LFW 局限性的分析不够深入**

epoch 17-20 验证 Dice 下降仅 0.0034（0.8729→0.8695），这在统计意义上几乎是噪声，称之为"过拟合"略有夸大。更准确的说法是：**验证 Dice 在 epoch 10 后趋于饱和（0.863±0.006），epoch 17 是随机波动中的峰值**，保存最优 checkpoint 是标准操作，防止随机性带来的次优结果。

**Q22. 分割结果有没有用于识别？如果没用，为什么要做分割？**

当前版本的分割模块是独立探索，未集成进识别流水线。做分割的原因有三：

① **课程要求**：数字图像处理课程设计要求覆盖图像分割相关内容，Phase 2 完整对比了四种传统方法（YCrCb/GMM/GrabCut/Watershed）和一种深度学习方法（ResUNet），满足课程要求。

② **方法探索**：通过比较各方法的前景占比和 IoU，得出了有价值的定量结论（GMM 过度分割、GrabCut 边界最优、ResUNet 高度一致且更平滑）。

③ **潜在应用路径**：分割掩膜可以用于遮挡检测（掩膜中异常区域 → 判断遮挡类型）、特征加权（前景像素权重更高）、数据增强等，是未来工作的基础设施。

**Q23. ResUNet 用 GrabCut 当伪标签，最终 Dice=0.8729，但如果 GrabCut 本身就错了怎么办？**

这是弱监督学习的固有局限。处理方式：

① **选优剔劣**：训练时过滤掉前景率 < 1% 的 GrabCut 空掩膜（约 3% 图像），避免错误标签。

② **模型有自纠正空间**：ResUNet 通过 9000+ 样本学习整体语义，部分样本的 GrabCut 错误会被其他样本"平均掉"。最终模型 FG ratio（28.9%）与 GrabCut 均值（28.9%）完全一致，说明模型确实做了一定程度的修正。

③ **上限认知**：用 GrabCut 伪标签训练的 ResUNet，理论上不可能在"正确答案"上超过一个用真实标注训练的模型。val Dice=0.8729 是对 GrabCut 标签的 Dice，而非对真实人脸轮廓的 Dice。如果用真实标注对比，实际质量未知。

**Q24. ArcFace 遮挡场景 A→B 只下降 3.54pp，这个下降是"大"还是"小"？**

需要参照系：

| 参照 | 数值 |
|------|------|
| 本项目 A→B | −3.54pp（92.65→89.11%）|
| MFR2021 报告口罩遮挡下降 | −10pp 到 −30pp（视遮挡程度）|
| 深色墨镜 B 最低 | 88.79%（−3.86pp）|

3.54pp 属于**轻度下降**，因为本项目的遮挡（水杯/眼镜/墨镜）保留了大部分面部区域，ArcFace 512-d 特征有足够冗余容纳局部遮挡。如果遮挡覆盖 50%+ 面部（如手托腮严重遮挡），下降幅度会更大。

**Q25. 项目中图像分割和人脸识别是两个独立部分，它们的联系体现在哪里？**

联系体现在**流水线的数据流**和**方法论层面**：

- **数据流**：Phase 1 预处理 → Phase 2 分割（理解图像结构）→ Phase 3 识别（建立基线）→ Phase 4 合成（利用关键点，与分割有相似的"理解图像结构"目标）→ Phase 5 鲁棒识别
- **方法论**：分割的目的是理解"人脸前景在哪里"，这与遮挡识别中"有效特征区域在哪里"是同一个问题的两种表述。GrabCut 的前景分割结果（前景约 24%）启发了级联策略中眼周裁剪的设计——眼周区域恰好是 GrabCut 前景的主要部分
- **ResUNet 的桥接作用**：ResUNet 生成的掩膜可以作为遮挡检测的辅助信号（若推理时某区域被预测为背景但实际是人脸位置，说明该区域被遮挡），这是未来整合的方向

**Q26. 合成遮挡数据和真实遮挡数据有多大差距？实验结论能推广吗？**

合成数据的局限：

① **Alpha Blending 过于理想**：真实遮挡（如手）有透光、阴影、形变，简单 Alpha 混合没有这些效果
② **遮挡位置固定**：同一身份每次都是相同锚点（嘴角/眼睛中心），真实场景位置随机
③ **贴图库有限**：cup 18 张、glasses/sunglasses 各 20 张，缺乏多样性

结论推广的边界：**定性结论（ArcFace 对轻度遮挡鲁棒，眼周局部裁剪不能直接改善）大概率成立**；定量数值（89.11%）则需在真实课堂数据上重新验证。合成数据实验是"概念验证"（Proof of Concept），而非生产级验证。
